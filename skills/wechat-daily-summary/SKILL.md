# 微信每日群聊总结

使用当前可用的 computer-use 技能和其支持的运行时操作微信。先读取该技能及必要文档，不复制固定版本路径、窗口句柄、坐标或 API 实现。本技能补充微信阅读流程，不替代底层操作规则。

## 确定范围

- “过去一天”默认以任务开始时刻为终点回溯 24 小时。“昨天”按自然日理解。记录起止时刻和时区，对照微信时间标签；界面日期或时区与运行环境不一致时先核实，不猜绝对日期。
- “折叠聊天前 N 个群”以首次打开列表时的顺序固定目标。记录群名和可见成员数，后续新消息改变排序时仍读取原目标。
- 进入各群后用标题核实名称，列表可能截断。名称看不清就暂称“第一个群”等，不凭相似字猜群名。

## 建立可读界面

- 从运行时返回的窗口中唯一选择微信，激活后重新观察。截图可能含遮挡窗口，不能把被遮住的聊天区当成已读取。
- 在有助于阅读时最大化微信。窗口改变后等待布局稳定并重新观察，废弃旧坐标。
- 先检查可访问性文本是否包含实际消息。若仅返回窗格节点，切换为截图阅读，不反复请求同样的空树。
- 翻页前点击已观察到的聊天记录空白处并检查焦点，避开输入框。微信滚轮曾出现位移很小的情况，若未有效移动，尝试 Page Up。键盘翻页也必须验证实际结果。

## 连续读取与留存证据

为每个群维护简短阅读记录，默认保留在当前任务上下文，不把群聊原文永久写入 skill：

| 字段 | 内容 |
| --- | --- |
| 目标 | 首次列表位置、核实的群名、成员数 |
| 时间范围 | 任务开始时确定的起止时刻 |
| 当前覆盖 | 已读最早和最晚时间 |
| 翻页锚点 | 当前页顶部和底部可辨认的消息片段 |
| 摘要证据 | 话题、时间、必要的发言者、具体信息 |
| 缺口 | 未加载、模糊图片、未读取附件或上下文缺失 |
| 状态 | 未开始、读取中、覆盖完成、部分完成 |

- 每次执行一个翻页动作，立即刷新并检查。若仍在加载或重排，先重新观察稳定后的页面，再决定下一个动作。不要连续盲翻或仅按调用次数推断进度。
- 相邻页应有可辨认的消息重叠。重复页不计入新进度；没有重叠则回翻或小幅移动补齐。时间跨度很大可能是聊天停顿，也可能是翻页遗漏，需通过消息锚点区分。
- 边读边合并同一话题，保留招聘地点、岗位要求、期限、明确行动事项等细节。转发内容和群友看法按来源表述，不当作已验证事实。
- 重要截图文字看不清时，可通过已观察到的图片入口放大查看。表情包无需逐张打开。文章、视频、语音和附件未实际读取时只概述可见标题或标记未读，不推断其正文。
- 新消息出现时保持已固定的时间终点与群目标，避免不断追逐最新消息。

## 完成标准与中断

只有同时满足以下条件，才称该群所需时间段覆盖完成：

1. 已读取终点附近的目标消息。
2. 已找到起点之前的消息或明确的历史记录起始边界。
3. 中间翻页连续，已发现的缺口得到补齐。

仅看到“昨天”的一条消息不代表读完过去一天。文字时间段覆盖完成也不等于所有媒体附件都读完。

若两次调整仍无法让页面推进，停止重复同一动作，检查焦点、窗口、加载状态或使用界面中实际可见的聊天记录入口。若仍无法推进，说明已读范围及阻碍。

用户按 Esc 或工具报告用户停止时，立即停止电脑操作。交付已读内容，明确尚未完成的群及时间范围，不为补全摘要继续调用电脑工具。

## 交付

按群分别给出主要讨论和有用信息，篇幅随内容调整。优先呈现招聘机会、已定事项、截止时间及需要用户处理的内容；一般闲聊简述。没有充分覆盖时，避免断言“没有重要消息”。

开头说明实际时间范围与完成度。有缺口时注明“已读取部分”，不要说“完整总结”或“全部读完”。不报告未经证据支持的精确消息数量。群名未核实则保留位置称呼。

进度更新只说明已确认的话题、覆盖到的时间及剩余工作，不逐页播报。交付前删去套话，使用简洁中文。若环境提供 unslop 技能，按其规则自查。
